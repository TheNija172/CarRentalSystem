# Car Rental System

Car Rental System is a backend application for managing car rentals. The system allows users to browse available cars, create and manage bookings, leave reviews, and make payments.

## Tech Stack

- Java 21
- Spring Boot 3.5.x
- Spring Data JPA
- Spring Security
- JWT
- PostgreSQL 16
- Flyway
- Maven
- Lombok
- MapStruct
- Springdoc OpenAPI / Swagger
- JUnit 5
- Mockito
- Docker
- Docker Compose

## Requirements

- JDK 21 or higher
- Maven 3.9 or higher
- Docker
- Docker Compose

## Running the Application

### Local Development

1. Start PostgreSQL:

```bash
docker compose up -d postgres
```

2. Build the project:

```bash
mvn clean package
```

3. Run the application:

```bash
mvn spring-boot:run
```

The application will be available at:

```text
http://localhost:8080
```

The local PostgreSQL database is available on port `5433`.

### Running with Docker

1. Build the project:

```bash
mvn clean package
```

2. Build and start the application and PostgreSQL:

```bash
docker compose up --build
```

The application will be available at:

```text
http://localhost:8080
```

To stop the containers:

```bash
docker compose down
```

To stop the containers and remove the database volume:

```bash
docker compose down -v
```

## Environment Variables

The following environment variables are supported:

| Variable | Description | Default |
|------------------|-------------------------------------|----------------------------------------------------|
| `DB_URL`         | PostgreSQL JDBC connection URL      | `jdbc:postgresql://localhost:5433/CarRentalSystem` |
| `DB_USERNAME`    | PostgreSQL username                 | `postgres`                                         |
| `DB_PASSWORD`    | PostgreSQL password                 | `postgres`                                         |
| `SERVER_PORT`    | Application HTTP port               | `8080`                                             |
| `JWT_SECRET`     | Secret key used to sign JWT tokens  | configured in `application.yml`                    |
| `JWT_EXPIRATION` | JWT expiration time in milliseconds | `86400000`                                         |
|------------------|-------------------------------------|----------------------------------------------------|

When running the application in Docker, the database URL is:

```text
jdbc:postgresql://postgres:5432/CarRentalSystem
```

## REST API Examples

### Register a User

```bash
curl -X POST http://localhost:8080/api/v1/auth/register   -H "Content-Type: application/json"   -d '{
    "name": "John",
    "surname": "Doe",
    "email": "john@example.com",
    "password": "password123"
  }'
```

### Login

```bash
curl -X POST http://localhost:8080/api/v1/auth/login   -H "Content-Type: application/json"   -d '{
    "email": "john@example.com",
    "password": "password123"
  }'
```

### Get Current User Bookings

Replace `YOUR_JWT_TOKEN` with the token returned by the authentication endpoint.

```bash
curl -X GET http://localhost:8080/api/v1/bookings/my   -H "Authorization: Bearer YOUR_JWT_TOKEN"
```

### Create a Booking

```bash
curl -X POST http://localhost:8080/api/v1/bookings   -H "Authorization: Bearer YOUR_JWT_TOKEN"   -H "Content-Type: application/json"   -d '{
    "carId": 1,
    "pickupLocationId": 1,
    "returnLocationId": 1,
    "startDate": "2026-09-01",
    "endDate": "2026-09-05"
  }'
```

## Testing

Run all tests with:

```bash
mvn test
```

Or with the Maven Wrapper on Windows:

```bash
mvnw.cmd test
```

The project uses JUnit 5 and Mockito for unit testing. Tests cover the main service-layer business logic, including successful operations, validation errors, missing resources, access restrictions, and business exceptions.

## Database

The application uses PostgreSQL 16 as its relational database.

Database schema migrations are managed with Flyway.

Hibernate is configured with:

```text
ddl-auto=validate
```

Therefore, database schema changes are managed by Flyway rather than being automatically generated by Hibernate.

## Security

The application uses Spring Security with JWT-based authentication.

After successful authentication, the client receives a JWT token. The token must be passed in the `Authorization` header:

```text
Authorization: Bearer <JWT_TOKEN>
```

Role-based authorization is used for protected administrative operations.
